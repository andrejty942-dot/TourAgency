## БАГ #001 - Отсутствует валидация пустых полей при авторизации

| Параметр | Значение |
|----------|----------|
| **ID** | BUG-001 |
| **Приоритет** | High (P1) |
| **Серьёзность** | Major |
| **Статус** | Open |
| **Модуль** | LoginWindow |
| **Версия** | 1.0 |

### Описание
Приложение не проверяет, заполнены ли поля логина и пароля перед попыткой авторизации. Пустые поля обрабатываются как неверные учётные данные.

### Шаги воспроизведения
1. Запустить приложение
2. Оставить поля "Логин" и "Пароль" пустыми
3. Нажать кнопку "Войти"

### Ожидаемый результат
Должно отображаться сообщение: "Введите логин и пароль"

### Фактический результат
Отображается сообщение: "Неверный логин или пароль"

### Дополнительная информация
**Файл:** `LoginWindow.xaml.cs`, строка 23-36  
**Код:**
```csharp
private void BtnLogInClick(object sender, RoutedEventArgs e)
{
    string login = Name.Text;
    string password = Password.Password;
    if (login == "agent" && password == "agent") // Нет проверки на пустоту
    {
        MainWindow mainWindow = new MainWindow();
        mainWindow.Show();
        this.Close();
    }
    else
    {
        MessageBox.Show("Неверный логин или пароль", "Ошибка", ...);
    }
}
```

### Предлагаемое решение
Добавить проверку перед сравнением:
```csharp
if (string.IsNullOrWhiteSpace(login) || string.IsNullOrWhiteSpace(password))
{
    MessageBox.Show("Введите логин и пароль", "Ошибка", ...);
    return;
}
```

## БАГ #002 - NullReferenceException при открытии окна добавления тура

| Параметр | Значение |
|----------|----------|
| **ID** | BUG-002 |
| **Приоритет** | Critical (P0) |
| **Серьёзность** | Critical |
| **Статус** | ✅ FIXED |
| **Модуль** | AddTourWindow |
| **Версия** | 1.0 |

### Описание
При открытии окна добавления тура происходит обращение к `NewTour` без проверки на `null`, что может привести к краху приложения.

### Шаги воспроизведения
1. Открыть главное окно
2. Нажать "Добавить тур"
3. Событие `Loaded` срабатывает

### Ожидаемый результат
Окно открывается с пустыми полями

### Фактический результат
**ДО ИСПРАВЛЕНИЯ:** Потенциальный `NullReferenceException` при попытке загрузить данные из `NewTour`

### Дополнительная информация
**Файл:** `AddTourWindow.xaml.cs`, строка 64-70 (до исправления)  
**Код (до исправления):**
```csharp
private void Loadedwin(object sender, RoutedEventArgs e)
{
    TxtHotel.Text = NewTour.Hotel; // NullReferenceException!
    TxtCity.Text = NewTour.City;
    TxtCountry.Text = NewTour.Country;
    TxtName.Text = NewTour.Name;
}
```

### Решение (реализовано)
```csharp
private void Loadedwin(object sender, RoutedEventArgs e)
{
    if (NewTour != null)
    {
        TxtHotel.Text = NewTour.Hotel;
        TxtCity.Text = NewTour.City;
        TxtCountry.Text = NewTour.Country;
        TxtName.Text = NewTour.Name;
    }
}
```

**Статус:** ✅ Исправлено в commit d98e687

```csharp
Status = statusItem.Content.ToString() // statusItem == null
```

**Файл:** `EditBookingWindow.xaml.cs`, строка 88

## БАГ #004 - Нет валидации формата email

### Описание
Поле "Email" принимает любой текст без проверки на корректность формата email-адреса. Пользователь может ввести "abc123" или "test@@mail", и данные сохранятся.

### Шаги воспроизведения
1. Открыть окно добавления бронирования
2. Заполнить все обязательные поля
3. В поле "Email" ввести "asdfghjkl"

Должно отображаться сообщение: "Введите корректный email адрес"

### Фактический результат
Бронирование сохраняется с некорректным email

### Предлагаемое решение
Добавить валидацию регулярным выражением:
```csharp
if (!string.IsNullOrWhiteSpace(TxtEmail.Text))
{
    string emailPattern = @"^[^@\s]+@[^@\s]+\.[^@\s]+$";
    if (!Regex.IsMatch(TxtEmail.Text.Trim(), emailPattern))
    {
        MessageBox.Show("Введите корректный email адрес", "Ошибка", ...);
        TxtEmail.Background = new SolidColorBrush(Colors.IndianRed);
        TxtEmail.BorderBrush = new SolidColorBrush(Colors.DarkRed);
```

### Описание
В методах добавления/редактирования данных отсутствуют try-catch блоки. Любое непредвиденное исключение приведёт к краху приложения.

Сложно воспроизвести без специальных условий, но риск есть при:

- Парсинге данных
- Работе с коллекциями

### Ожидаемый результат

### Фактический результат
Приложение аварийно завершается

### Предлагаемое решение
Обернуть критические операции в try-catch:
```csharp
private void BtnAddClick(object sender, RoutedEventArgs e)
{
    try
    {
        // вся логика валидации и сохранения
    }
    catch (Exception ex)
    {
        MessageBox.Show($"Произошла ошибка: {ex.Message}", 
            "Ошибка", MessageBoxButton.OK, MessageBoxImage.Error);
    }
}
```
